## Database schema summary (from `supabase_backup.sql`)

### 7 tables in `public`

| Table | Purpose | Key columns |
|---|---|---|
| `project_types` | Lookup: technology kind deployed | `id` (PK), `name` (UNIQUE, varchar(100)) — seed: Portasol, Water Pump, Solar Dryer, Vermi Composting |
| `beneficiaries` | Organizations receiving projects | `id` (PK), `name`, `category` (enum), `district`, `municipality`, `barangay` |
| `beneficiary_contacts` | People at each beneficiary | `id` (PK), `beneficiary_id` (FK → beneficiaries, ON DELETE CASCADE), `name`, `role`, `contact_number`, `messenger_link` |
| `project_instances` | **Central table** — one row per deployed project | `id` (PK), `year`, `project_type_id` (FK), `beneficiary_id` (FK, NO ACTION — no cascade), plus demographics, status enums, gdrive_folder_link, created_at/updated_at |
| `document_types` | Lookup/template: what documents should exist | `id` (PK), `name`, `is_default`, `phase` (enum), `applies_to` (enum), `is_required` — UNIQUE(name, phase) |
| `documents` | Per-project checklist rows | `id` (PK), `project_id` (FK → project_instances, ON DELETE CASCADE), `document_type_id` (FK, nullable), `custom_label`, `expected_date`, `submitted`, `submitted_date`, `notes`, `has_hard_copy`, `hard_copy_claimable`, `gdrive_link`, `is_not_applicable` — CHECK: document_type_id IS NOT NULL OR custom_label IS NOT NULL |
| `remarks` | Leveled commenting/audit (apparently unused) | `id` (PK), `project_id` (FK, ON DELETE CASCADE), `level` (enum: provincial/regional/pcest/rcest), `content`, `added_by` (free text, no user FK), `created_at` |

## Row Level Security (RLS)

**Enabled on all 7 public tables.** Each has three overlapping policies:

1. `"Allow anon read"` — SELECT only, role `anon`, `USING (true)`
2. `"Allow authenticated users"` — all operations, role `authenticated`, `USING (true) WITH CHECK (true)`
3. `"allow all"` — all operations, **no role restriction**, `USING (true) WITH CHECK (true)`

Because policy #3 applies to every role including `anon`, **anonymous users have full read/write access to every table**. This is documented as a finding, not fixed. Combined with no auth UI in the app, current real-world access control is **none**.
